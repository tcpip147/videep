# 런타임 공개 계약

## 구성 계약

실행 구성은 다음 정보를 제공한다.

- 입력과 출력의 위치 및 압축 형식
- 사용할 백엔드와 장치 선택 조건
- 전처리·추론·후처리별 `module:object` 참조
- 단계별 큐 용량(기본값 4)
- 오류 및 종료 정책
- 요구하는 픽셀 형식, 크기와 성능 측정 설정

알 수 없는 항목, 중복 단계, 1 미만 큐 용량 또는 다중 입력·출력 구성은 시작 전에 거부한다.

## 백엔드 계약

백엔드는 장치와 capability 열거, 디코더·인코더 생성, GPU 리소스 pool, 동기화 wait/signal,
GPU 시간 및 메모리·전송 계측을 제공해야 한다. 네이티브 형식은 백엔드 밖으로 노출하지 않는다.
호환되는 무복사 경로가 없으면 CPU 폴백 없이 협상 실패를 반환한다.

## 알고리즘 단계 계약

전처리, 추론 및 후처리 구성요소는 다음 수명 주기를 각각 구현한다.

```text
validate(capabilities) → initialize(context) → process(frame_view) → close()
```

- `process`는 호출 범위에서만 `FrameView`를 사용한다.
- 구성요소는 `GpuFrame`이나 기반 GPU 리소스의 소유권을 보관하지 않는다.
- tensor 접근은 복사 금지와 소비자 스트림 전달을 지원하는 DLPack 뷰를 사용한다.
- 출력은 새 프레임 lease 또는 동일 프레임과 갱신된 동기화 토큰이어야 한다.
- 전체 프레임의 호스트 메모리 변환 요청은 계약 위반이다.
- 예외는 런타임이 단계 오류로 변환하고 입력 lease를 회수한다.

## 제어 플레인 계약

지원 명령은 `start`, `stop`, `status`이다. 상태 이벤트는 실행 상태, 오류, 프레임 카운트,
큐 통계와 성능 메트릭을 전달할 수 있다. 명령과 이벤트에는 전체 프레임 픽셀 데이터나 GPU
리소스 핸들을 포함하지 않는다.

## 데이터 플레인 계약

단계 간 FIFO 항목은 `GpuFrame` lease 또는 명시적 `EOS`/`ERROR` 신호다. 큐는 제한된
용량과 순서를 보장하며 가득 차면 상류를 대기시킨다. 제어 플레인의 정체는 데이터 소유권
이전에 영향을 주지 않으며 데이터 플레인의 정체는 오류·중지 명령을 차단하지 않는다.

## 호환성 및 오류

계약은 명시적 버전을 가진다. 주 버전 불일치, capability 교집합 부재, 장치 불일치,
소유권 중복, 만료된 뷰 접근 또는 동기화 순서 위반은 처리 시작 전 또는 발견 즉시 실패한다.
오류는 실행, 단계, 프레임 식별자(있는 경우), 원인과 회수 결과를 포함한다.
