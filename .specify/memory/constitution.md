# Videep 프로젝트 헌법

## 핵심 원칙

### I. GPU 상주 데이터 경로

비디오 프레임 데이터는 디코딩 → 전처리 → 추론 → 후처리 → 인코딩의 전체
데이터 경로에서 반드시 GPU에 상주해야 한다. 정상적인 프레임 처리 과정은
GPU → CPU → GPU 왕복을 요구해서는 안 된다. 별도의 명세가 명시적으로 허용하지
않는 한, 프로덕션 데이터 경로에서 CPU가 전체 프레임 픽셀 데이터에 접근하는 것을
금지한다. 이는 불필요한 전송 지연과 메모리 대역폭 소비를 방지하고 처리량을
예측 가능하게 유지하기 위한 비타협적 원칙이다.

### II. 백엔드 독립성

핵심 파이프라인 추상화는 특정 GPU 공급업체, 운영체제 또는 그래픽 API에 의존해서는
안 된다. GPU별 구현은 반드시 백엔드 인터페이스 뒤에 격리해야 한다. 핵심 파이프라인은
CUDA, Vulkan, VA-API, Direct3D 또는 Metal 형식을 직접 사용하지 않고 추상 GPU 리소스를
통해 동작해야 한다. 이는 파이프라인 의미론을 유지하면서 지원 장치와 플랫폼을 교체하거나
확장할 수 있도록 보장하기 위한 비타협적 원칙이다.

### III. 기본 데이터 모델로서의 GpuFrame

`GpuFrame`은 파이프라인 내부 비디오 프레임 데이터의 표준 표현이어야 한다. NumPy 배열,
`Vec<u8>` 또는 이에 상응하는 호스트 메모리 버퍼 같은 CPU 이미지 표현을 비디오 프레임
픽셀 데이터의 주 파이프라인 표현으로 사용해서는 안 된다. `GpuFrame`은 기반 GPU 리소스의
소유권, 수명, 형식, 장치 및 동기화 요구사항을 보존해야 한다. 이를 통해 각 처리 단계가
리소스 계약을 명시적으로 준수하고 암묵적인 복사나 수명 오류를 방지한다.

### IV. 데이터 플레인과 제어 플레인의 분리

대용량 비디오 데이터는 애플리케이션의 제어 플레인 이벤트 버스를 통해 전달해서는 안 된다.
데이터 플레인은 GPU 리소스의 소유권과 역압을 처리하기에 적합한 전용 프레임 큐, 풀 또는
스트리밍 메커니즘을 사용해야 한다. 제어 플레인은 명령, 구성, 수명 주기 이벤트, 오류,
메트릭 및 추론 메타데이터를 전달할 수 있다. 이 분리는 대용량 프레임 전송이 제어 메시지의
지연과 안정성을 훼손하지 않도록 보장한다.

### V. 측정 가능한 성능

성능과 관련된 아키텍처 주장은 반드시 측정 가능한 근거로 뒷받침해야 한다. API가 명시적인
메모리 복사 연산을 노출하지 않는다는 이유만으로 파이프라인을 무복사로 간주해서는 안 된다.
GPU/CPU 전송, 동기화 지점, 버퍼 소유권, 지연 시간, 처리량 및 메모리 사용량을 측정할 수
있어야 한다. 성능 회귀는 자동화되거나 문서화된 벤치마크를 통해 재현 가능해야 한다.

### VI. 사용자 제공 알고리즘 런타임

파이프라인은 외부 Python 모듈로 구현된 사용자 제공 알고리즘 구성요소를 지원해야 한다.
전처리, 추론 및 후처리는 핵심 파이프라인 런타임을 변경하지 않고 각각 독립적으로 교체할
수 있어야 한다. 파이프라인 런타임은 비디오 전송, GPU 리소스 관리, 스케줄링, 동기화 및
수명 주기 관리를 소유해야 한다.

Python 구성요소는 정의된 런타임 인터페이스를 통해 동작해야 하며 기반 파이프라인 GPU
리소스의 소유권을 요구해서는 안 된다. 지원되는 무복사 상호운용 메커니즘을 통해 GPU 상주
데이터에 접근할 수 있지만, 정상 파이프라인 경로에서 전체 비디오 프레임을 GPU에서 CPU로
전송하도록 요구해서는 안 된다. 이를 통해 사용자 알고리즘의 확장성을 제공하면서 런타임의
리소스 안전성과 GPU 상주 경로를 보존한다.

### VII. 한글 명세

프로젝트의 모든 명세 문서는 반드시 한글로 작성해야 한다. 고유명사, API 식별자,
코드, 명령어처럼 번역하면 정확성이 훼손되는 요소는 원문을 병기하거나 그대로 사용할
수 있으나, 요구사항과 인수 조건 및 설계 의도에 대한 설명은 한글이어야 한다. 이를 통해
프로젝트의 의사결정과 검토 기준을 일관되게 공유한다.

### VIII. Python 표준 언어

프로젝트의 애플리케이션 및 데이터 처리 로직은 반드시 Python으로 구현해야 한다.
GPU 런타임, 코덱, 장치 드라이버 또는 성능상 필수인 네이티브 구성요소를 Python에서
호출하는 것은 허용하지만, 해당 통합의 제어 경로와 공개 인터페이스는 Python이어야
한다. Python 이외의 구현이 필요하면 도입 전에 명세에서 필요성, 범위, 대안 및 GPU
상주 데이터 경로에 미치는 영향을 명시적으로 승인받아야 한다.

## 기술 제약

- 프레임 단계 간 인터페이스는 GPU 메모리 객체, 장치 포인터 또는 무복사 상호운용
  메커니즘을 사용해야 한다.
- 프레임 데이터 인터페이스는 `GpuFrame`을 사용해야 하며, 리소스 소유권과 수명 및
  동기화 책임을 계약에 명시해야 한다.
- 데이터 플레인의 큐와 풀은 제한된 용량과 명시적인 역압 정책을 제공해야 하며, 전체
  프레임 픽셀 데이터를 제어 플레인 메시지에 포함해서는 안 된다.
- 핵심 파이프라인 모듈은 공급업체 SDK나 운영체제 및 그래픽 API의 구체 형식을
  가져오거나 공개 인터페이스에 노출해서는 안 된다.
- 각 GPU 백엔드는 공통 추상 GPU 리소스 계약을 구현해야 하며, 백엔드 전용 형식 변환은
  해당 백엔드 구현 내부에서만 수행해야 한다.
- 동기화, 메모리 복사 및 장치 간 전송은 코드와 성능 검증에서 식별 가능해야 한다.
- 로그, 메타데이터 및 집계된 측정값은 CPU에서 처리할 수 있지만, 전체 프레임 픽셀
  데이터의 CPU 접근을 우회적으로 허용해서는 안 된다.
- CPU 접근 예외는 기능 명세에 대상 단계, 목적, 데이터 범위, 성능 영향 및 제거 조건을
  포함해야 한다.
- Python 의존성은 GPU 버전과 실행 환경의 호환성을 재현 가능하게 고정해야 한다.
- 사용자 제공 Python 모듈의 전처리, 추론 및 후처리 인터페이스는 각각 독립적으로
  교체하고 계약 테스트할 수 있어야 한다.

## 개발 워크플로 및 품질 관문

- 명세 검토 시 한글 작성 여부, Python 사용 여부, GPU 상주 경로 준수 여부 및 백엔드
  독립성 준수 여부를 반드시 확인한다.
- 데이터 경로 변경은 디코딩부터 인코딩까지의 메모리 위치와 복사 경계를 보여 주는
  검증 근거를 포함해야 한다.
- 정상 처리 경로에 GPU → CPU → GPU 왕복이 없음을 자동화된 통합 테스트, 프로파일링
  결과 또는 동등한 측정 가능한 증거로 입증해야 한다.
- 성능 변경은 GPU/CPU 전송, 동기화 지점, 버퍼 소유권, 지연 시간, 처리량 및 메모리
  사용량을 재현 가능한 벤치마크로 비교해야 한다.
- 데이터 플레인 역압과 `GpuFrame`의 소유권 및 수명 계약은 부하 테스트와 실패 경로
  테스트를 통해 검증해야 한다.
- 사용자 제공 Python 모듈의 계약 테스트는 단계별 독립 교체와 정상 경로의 전체 프레임
  GPU → CPU 전송 금지를 입증해야 한다.
- 핵심 파이프라인의 백엔드 계약 테스트는 최소 하나의 대체 구현 또는 테스트 대역으로
  특정 GPU API 형식 없이 동작함을 입증해야 한다.
- 헌법의 예외를 사용하는 변경은 해당 예외를 승인한 명세를 참조해야 하며, 코드 검토자는
  예외의 범위가 명세를 넘지 않는지 확인해야 한다.
- 품질 관문을 통과하지 못한 변경은 병합하거나 프로덕션에 배포해서는 안 된다.

## 거버넌스

이 헌법은 프로젝트의 다른 모든 개발 관행과 문서보다 우선한다. 헌법 개정은 변경 이유,
영향받는 원칙, 기존 구현의 마이그레이션 계획 및 버전 변경 근거를 문서화하고 승인받아야
한다. 버전은 의미적 버전 규칙을 따른다. 원칙의 제거 또는 호환되지 않는 재정의는 주 버전,
새 원칙이나 실질적으로 확장된 의무는 부 버전, 의미를 바꾸지 않는 명료화는 수정 버전을
올린다.

모든 기능 명세와 코드 검토는 이 헌법의 준수 여부를 확인해야 한다. 위반이 발견되면 병합
전에 수정하거나, 이 헌법이 허용하는 명시적 예외를 명세에 기록해야 한다. 정기적인 품질
검토에서는 GPU 상주 데이터 경로와 성능 주장의 측정 근거, 백엔드 경계, `GpuFrame`
계약, 데이터/제어 플레인 분리, 사용자 알고리즘 인터페이스, Python 이외 구성요소의
승인 상태 및 명세의 한글 작성 상태를 점검한다.
